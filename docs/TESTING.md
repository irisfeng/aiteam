# AITeam 完整测试方案（模型 / MCP / Skills / 协作闭环）

> 目标：用真实模型跑通核心闭环，检验**拆解质量 / 验收严格度 / 插话响应 / 汇总水平 / 格式遵循度**
> 这五个只有真 key 才能验证的环节。每步给出「操作 → 预期 → 重点观察」，✅ 处可勾选。
>
> **测试分两层**：
> - **机制层（已自动化）**：`npm run build && npm test` 跑完整回归（DAG 调度/计划把关/
>   停止/预算/断点恢复/聊天管线/引用回复/交付格式/技能 CRUD/MCP 连接·容错·环境变量·去重/
>   用量/导出/角色模板幂等/频道管理/记忆/密钥脱敏/鉴权与多租户隔离/pptx 模板解析与就地改文图/
>   真 .pptx 导出/上传来源与定向润色/markitdown 端到端/验收者按类型路由/无源数字软门/
>   Helio 式多角色项目全链路：claim→阻塞输入→审批恢复→复核退回→返工交付→汇总→人类关闭/
>   模型供应商连通性测试/
>   产品内核心场景库：协作演练/调研报告/方案演示），Mock 模式零 token，提交前必跑；用例数量以命令输出为准。
> - **客户端烟测（已自动化）**：`npm run client:smoke` 会构建生产产物，用临时数据目录启动
>   `server/dist/index.js`，验证 `/aiteam/` 页面、standalone 登录、bootstrap、核心场景启动和 WebSocket
>   项目/任务/活动实时更新。
> - **真实浏览器 UI 烟测（本机可选）**：`npm run ui:smoke` 会启动隔离生产服务和系统 Chrome，
>   在桌面/移动视口真实渲染任务运行线、端到端验收、任务详情抽屉、复核清单和活动日志，并把截图写到
>   `output/ui-smoke/`。若 Chrome 不在默认路径，可设置 `AITEAM_UI_CHROME=/path/to/chrome`。
> - **智能层（需真实 key 人工执行）**：即本清单的 B2、C1-C4 的质量观察项、D1、G1/G3/G5
>   的行为观察项——机器只能验证"流程对不对"，"干得好不好"要靠你按 F 段回报。

## A. 环境准备

- [ ] **A1 拉取并构建**
  ```bash
  git pull && npm install && npm run build && npm start
  ```
  打开 `http://localhost:8787`。
  （开发模式 `npm run dev` 用 `http://localhost:5173`，热更新；二选一即可）

- [ ] **A2 确认初始态**：左侧能看到 4 位内置同事（产品经理 / 工程师 / 代码评审 / SEO 优化师）、
  侧栏视图：📥 收件箱、✅ 任务、📄 文档、👥 团队。左下角应显示 **Mock** 徽标（还没配 key）。

- [ ] **A3 配置模型供应商**：点左下角 **⚙** → 「模型供应商」。建议先只配一家主通道，跑通后再加第二家做对照。
  可先点 **DeepSeek / SiliconFlow GLM / 百炼 DashScope** 预设卡自动填入协议路径和模型名，再手动填 API Key。

  | 供应商 | Base URL | 默认模型 | 轻量模型 | 备注 |
  |---|---|---|---|---|
  | DeepSeek Anthropic | `https://api.deepseek.com/anthropic` | `deepseek-v4-pro` | `deepseek-v4-flash` | 可尝试勾选“服务端联网工具”，不支持会自动降级 |
  | SiliconFlow GLM | `https://api.siliconflow.com/v1` | `zai-org/GLM-5.2` 或控制台模型 ID | 选同供应商低成本模型 | OpenAI-compatible，联网优先用 MCP |
  | 百炼 / DashScope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` 或控制台当前模型名 | `qwen-turbo` | OpenAI-compatible；生产可替换为工作空间专属域名 |

  通用字段：
  - **API Key**：填对应平台 key；编辑时留空 = 保持原 key。
  - **单次输出上限**：先用默认 `16000`；若供应商限额较小，再下调。
  - **价格**：可选填输入/输出每百万 token 单价和币种；只用于任务演练的估算成本展示，不等同于供应商账单。
  - **⭐ 用作强通道**：建议勾在质量最好的一家上，验收与项目汇总优先走它。
  - **服务端联网工具**：只建议 Anthropic-compatible 端点勾选；OpenAI-compatible 通道会自动关闭，联网用 MCP。

  保存后先点该供应商行内 **测试**。预期返回 `可用 · OpenAI/Anthropic · 模型名 · 延迟`；
  若失败，优先检查 Base URL、模型名和 key。测试通过后 **Mock 徽标应消失**，这一步即把内置同事接到工作区默认模型通道。
  首次接入也可以勾选 **保存后立即跑任务演练**：系统会创建一条诊断任务，验证工具调用、文档交付、
  验收和可计费用量归因（billable tokens）；若填了价格，还会展示估算成本，并提供「打开任务」入口查看活动日志与交付物。

- [ ] **A4 配置 MCP**：⚙ → 「MCP 插件」。先接一个搜索类 MCP（Tavily / Bocha / 智谱搜索择一），安全级别选 `network`。
  - HTTP MCP：填 URL 和 token，点「测试」应返回工具数。
  - stdio MCP：填 command / args / env；env 只回显 key 名，不回显密钥值。
  - 高风险 `exec` 插件不要先开；要开也必须验证审批门。

- [ ] **A5 配置 Skills**：⚙ → 「技能」。先启用 2 个窄技能即可：
  - 交付自查 / 验收清单类：用于提高交付物可验收性。
  - 来源约束 / 定向润色类：用于上传资料后的受限改写。
  暂时不要一次性启用大量宽泛技能，否则会增加上下文噪声。

- [ ] **B1 基础聊天**：在 `#general` 发 `@产品经理 用三句话介绍你自己和你的工作方式`

  - 观察：回复是否中文、是否符合"先结论"的人设。

- [ ] **B1.5 任务页启动前检查**：进「✅ 任务」页，查看「任务运行线」里的 **启动前检查**。

  - 点 **模型通道 / 联网 MCP / 工作方法** 检查项，应分别打开设置里的「模型供应商 / MCP 插件 / 技能」页签；点协作频道应进入团队页。
  - 点 **配置链路验收** 后，所有已保存 key 的模型供应商都应各自生成一条同构任务演练，并与 MCP / Skills 演练一起归入同一个配置验收项目；页面会显示模型对比摘要、延迟、billable tokens 和可选估算成本，也可逐条打开任务详情对比活动日志、交付物、验收和用量归因。刷新页面后摘要应能从项目任务和结构化活动日志恢复。
  - 预期：右侧 **需要你处理** 面板会优先列出待审批、等待输入、待复核任务；无待处理事项时显示空状态。
  - 点绑定任务的待审批/等待输入项，应打开任务详情；可在「审批与输入」里直接批准/拒绝或确认恢复/保持阻塞。
  - 在「收件箱」处理审批/输入后，应刷新工作区并自动打开关联任务详情，能直接看到任务恢复、保持阻塞或继续执行后的最新状态。
  - 预期：下方可选 **协作演练 / 调研报告 / 方案演示** 三类核心场景。
  - 点任一场景后，应创建带依赖的项目并自动打开第一张任务详情。
  - 任务详情里的「依赖 / 后续」任务应可点击跳转，便于沿 DAG 追踪前置交付和下游任务。
  - 任务进入待复核后，任务详情应显示 **人工复核清单**：验收标准逐条列出，并汇总交付物、自查表、复核事件、待处理审批/输入状态；关单前应先在这里核对。
  - 项目组卡应显示整体进度、状态构成和下一步提示；可直接打开「最终汇总」或最新交付物；全部交付后可在待评审列一次性关闭项目。
  - 桌面端 deep link 可直接定位：`aiteam://task/<taskId>` 打开任务详情，`aiteam://approval/<approvalId>` 打开并高亮收件箱审批；首次使用引导不应遮挡 deep link 目标。
  - 桌面端任务待评审、任务阻塞、审批待处理通知可点击，并打开对应任务或审批。

- [ ] **B2 联网能力探针**（优先验证 A4 的 MCP 是否可用）：
  发 `@SEO 优化师 搜一下 2026 年最新的开源 ASR 模型有哪些，列 3 个`
  - ✅ 若正常返回带来源的结果 → MCP 搜索链路可用。
  - ❌ 若模型报 web tool 相关 400 → 回 ⚙ 编辑供应商，取消勾选“服务端联网工具”，改用 MCP 搜索。
  - ❌ 若 MCP 报连接/鉴权错误 → 先在 MCP 插件页点「测试」，确认 URL/token/env。

## C. 核心闭环（重头戏）

### C1 单任务自动执行 + 验收循环
- [ ] 进「✅ 任务」页 → 右上「快速新建任务」填
  `调研 Fun-ASR 的微调方式并给出要点清单` → 指派下拉选 **工程师** → 新建。
- 预期顺序（频道里会刷出系统事件）：
  `🚀 开始处理` → （可能 `web_search`）→ `📄 写好了文档` → `🔎 代码评审 开始验收` →
  `✅ 验收通过` 或 `↩️ 退回修订` → `📦 已交付，转入待评审`。
- 观察重点：
  - **验收是否真的在审**：看代码评审那条消息，是逐条对照验收标准，还是走过场？
  - 任务卡停在「待评审」列、**不会自动进「完成」**（关单是 human-only）。
  - 卡片底部出现「📄 交付物」入口，点开能读全文。

### C2 项目模式 · 全自主（auto）——最关键
- [ ] 在 `#general` 对产品经理下一个**需要分工**的目标：
  ```
  @产品经理 立项并全自主完成：调研 2026 年三款主流开源中文 ASR 模型
  （准确率、推理成本、微调难度），最终交付：①一份选型分析报告 ②一份汇报演示文稿
  ③一张三模型对比数据表。你来拆解分工、并行推进，最后汇总。
  ```
- 预期：
  - 频道出现 `🧩 立项「…」，共 N 个任务` + 任务清单（带依赖关系）。
  - 「任务」页看到多张卡片自动 `todo→doing`，**有依赖的会等前置交付后才开工**
    （卡片上有 `⛓ 依赖` 徽标）。
  - 全部交付后：`🎯 全部任务已交付，产品经理开始汇总` → `🏁 已汇总交付`。
- 观察重点（这就是真 key 才能看的东西）：
  - **拆解质量**：任务切分是否合理？依赖关系对不对（对比表是否依赖三个调研任务）？
  - **并行度**：无依赖任务是否真并行跑起来了？
  - **汇总水平**：最终汇总报告是否真的综合了各交付物、消解了矛盾，而非简单拼接？

### C3 项目模式 · 计划把关（approve_plan）
- [ ] 新开一句（或在新频道）：
  ```
  @产品经理 立项，但先把计划给我看、我批准后再开工：撰写一篇关于"AI 数字员工"的科普长文，
  要求有大纲、正文、配图建议。
  ```
- 预期：进「📥 收件箱」看到一条 **🧩 项目计划** 审批，列出任务计划；任务**不会自动开工**。
  - [ ] 点「批准」→ 频道刷出 `▶️ 计划已获批准，开工`，任务开始执行。
  - [ ] （可选另测）点「拒绝」→ 应刷出 `✋ 计划被退回`，产品经理被唤起请你给意见。
- 观察：批准前任务确实**纹丝不动**；拒绝后 Lead 是否会结合你频道里的意见重新拆？

### C4 运行中插话（人随时干预）
- [ ] 在 C2 或 C3 某个任务**正在 doing 时**，于频道里发一句纠偏指令，例如：
  `补充一句：对比表里一定要包含"是否支持流式识别"这一列`
- 预期：该指令会注入正在工作的同事的下一轮迭代。
- 观察：后续交付物里**是否真的纳入了**你的临时要求。

### C5 停止开关
- [ ] 某任务 doing 时，到「任务」页点该卡片的 **⏹** 按钮。
- 预期：频道 `⏹ 已被用户停止，退回待办`，卡片回到「待办」列。

## D. 治理与边界

- [ ] **D1 审批门（高风险动作）**：发
  `@SEO 优化师 起草一封给潜在客户的推广邮件，写好后准备发送`
  - 预期：进「📥 收件箱」出现一条**动作审批**（邮件全文），SEO **不会**自称已发送。
    批准/拒绝后频道有回执。

- [ ] **D2 记忆复利**：先发 `@产品经理 记住：我们公司的产品叫 KgLand，目标用户是中小企业。`
  之后**新开一个任务**指派给产品经理，看交付物里是否自然带上了 KgLand / 中小企业的背景。

- [ ] **D3 团队视图**：进「👥 团队」，在有任务跑的时候观察——
  每位同事的**忙/闲状态、当前任务、队列深度、今日交付数、今日 token 用量**是否实时更新（4 秒刷新）。

- [ ] **D4 例行任务**：发
  `@产品经理 以后每天 09:30 在这里发一份昨日进展与今日计划的站会汇总`
  - 预期：频道 `⏰ 设置了每日 09:30 的例行任务`，「团队」页底部「例行任务」可见、可删除。
  - （想立刻验证触发，可把时间设成**下一分钟**，等调度器 30s 粒度触发。）

- [ ] **D5 断点恢复（durability）**：某任务 doing 时，**Ctrl+C 停掉服务**，再 `npm start`。
  - 预期：启动后频道刷出 `🔁 服务重启，恢复执行任务「…」`，任务自动续跑至交付。

- [ ] **D6 预算护栏（可选）**：用 `AITEAM_DAILY_TOKEN_BUDGET=50000 npm start` 启动，
  跑几个任务把当日用量顶上去，新任务应出现 `🧯 今日 token 预算已用尽，暂停自动开工`。

## G. M6 新能力（MCP / 技能 / 引用回复）

- [ ] **G1 MCP 接入**：⚙ → MCP 插件 → 按 GUIDE.md 推荐接入 Tavily（远程 HTTP）→
  「测试」应返回工具数。然后发：`@调研员 用 tavily 搜一下今天的 AI 行业新闻，给 3 条带来源`

- [ ] **G5 轻量档位实测**：供应商配好轻量模型后，立项一个含"格式整理"类子任务的项目 →
  看板该任务卡应带 ⚡ 轻量徽标 → 用量账本中该次执行的模型应为 flash。

## H. 产出质量轮（真 .pptx / ECharts 图表 / 配图 / 强通道）

- [ ] **H1 真 .pptx 导出**：点开任意 slides 文档 → 标题栏新增 **「⬇ .pptx」** →
  下载后用 PowerPoint / WPS / Keynote 打开。
  - 预期：可编辑文本（不是图片贴片）、16:9、暖白+琥珀主题、标题页+内容页+页码；
    Markdown 里的 `<!-- note: … -->` 应出现在**讲者备注**里。
- [ ] **H2 ECharts 图表**：点开 sheet 文档 → 「📊 图表」→ 应是交互式图表，
  可切 **柱状 / 折线 / 饼图**；多个数值列自动成多系列（带图例）；悬浮有 tooltip；深浅主题配色跟随。
- [ ] **H3 配图生成（需火山方舟 key）**：⚙ → 模型供应商 → 底部 **🎨 图像生成（Seedream）**：
  填方舟 API Key + 接入点 ID（如 `doubao-seedream-5-0-260128`，以控制台为准）→ 保存。
  然后派一个"做一份产品介绍 PPT，封面要有配图"的任务。
