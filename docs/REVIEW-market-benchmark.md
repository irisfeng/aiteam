# AITeam 市场对标与优化方向评估（2026-07）

> 方法：两路联网调研（海外线约 23 次检索 / 国内线约 24 次检索，关键事实带来源域名+日期）
> + 内部证据（DESIGN.md 路线图、harness-analysis 弱点盘点、EXTERNAL_AGENT_ADAPTER 契约草案）。
> 结论以「可极大推进的方向」为交付重心，每个方向落到代码路径。

---

## 0. TL;DR

1. **底层假设已被市场验证，且正在变成入场券**：2026 上半年 Helio、Dust（4000 万美元 B 轮）、
   OpenAI Workspace Agents、Anthropic Claude Cowork/Managed Agents 几乎同时收敛到
   「人机同一工作面」叙事。方向对，但「同台」本身不再构成差异化。
2. **AITeam 手里有一张全行业几乎没人打的牌**：项目 DAG 调度 + 干净上下文机器验收 +
   有界返工闭环。两路调研均未发现成熟复制品——这是当前最真实的护城河，应当**产品化、
   显性化**，而不是继续作为内部机制。
3. **窗口不大**：国内 2026 是「本地优先多 Agent 团队」概念集中爆发年（Marvis、AutoClaw、
   OpenClaw 系、Eigent、AionUi、OpenWork），飞书 Aily 在叙事上最接近但走云 SaaS 路线。
   自建频道 + 本地优先 + 国产模型通道的组合位当前无人卡住。
4. **优先推进六个方向**（按影响/成本/窗口排序）：质量闭环产品化 → 成本可预测性 →
   团队知识底座 → BYOA 编码会话 → IM 旁挂触达 → MCP/A2A 互操作。前两个是低成本高辨识度
   的「放大现有优势」，后四个是补齐决定天花板的能力缺口。

| **Anthropic Cowork / Managed Agents** | 企业 agent 工作台 + 托管运行时 | 潜在竞争者兼生态伙伴 | 2026-04-09 三连发：Cowork GA、Managed Agents 公测、Skills 开源（thenewstack.io, 2026-04） |

| Lindy / Relevance AI | 个人/企业自动化 | 相邻品类 | 共同痛点被用户点名：credit 消耗不可预测、多租户凭证隔离difficile（trustpilot/g2, 2026） |

### 1.2 国内：无直接同形态成熟竞品，但新势力密集涌入

| 阵营 | 代表 | 与 AITeam 的关系 |
|---|---|---|
| 大厂平台 | 扣子 Coze（已开源）、钉钉 AI 助理、**飞书 Aily** | Aily「数字员工，一次搭建全团队共享」叙事最接近，但云 SaaS、不可自部署——与我们互为镜像两极 |
| 通用超级智能体 | Manus（ARR 破亿美元）、Genspark、MiniMax Agent、AutoGLM、Kimi（K2.6 单 Swarm 300 子 agent） | 全部是「单任务框」心智，无团队协作看板；内部多 agent ≠ 对外团队形态 |
| 桌面多 Agent | 腾讯 Marvis（6 个常驻 agent）、AutoClaw、MaxClaw | C 端 PC 管理场景；证明「本地多 agent 编队」心智已被教育 |

| 开源同构 | **Eigent**（CAMEL 系桌面多 agent 团队）、**AionUi**（12+ CLI agent 统一壳）、**OpenWork**（Cowork 开源平替，1 万星） | 形态最接近的三个项目，**均缺 DAG 调度与验收返工闭环**；尚无国产化分支（钉钉/飞书对接 + 国产模型通道） |
| RPA+LLM | 实在智能、来也、澜码（已陷困境） | 强流程自动化/私有化交付，弱知识型团队敏捷协作；澜码资金链断裂是赛道警示 |

### 1.3 六个行业级信号（2026）

1. 「人机同台」成默认范式 → 分化点转移到**审批机制、记忆质量、协作可观测性**；
2. **MCP 管工具、A2A 管 agent 通信**成共识架构（100+ 企业采用、首份联合互操作规范预计 2026 Q3）——互操作从加分项变企业采购默认预期；
3. 计费从按坐席转**按用量/按结果**（混合计费采用率 27%→41%）；**成本可预测性是全行业通病**（Lindy/Relevance/Agentforce 均被点名）；
4. **治理/身份/审计成企业硬门槛**（Agent 365 把 agent 当员工纳管）；
5. **evals 谈得多做得少**：仅 52% 做评测；做了 prompt 变更自动评测的 agent 回滚率 9%，没做的 47%——内建 evals 是明确空白；
6. 多 agent 团队叙事溢出编程领域，向全职能蔓延；但「AI 互相评审/挑战」**没有任何产品给出可复现、可观察的设计范式**。

## 3. 可极大优化推进的方向（按优先级）

### D1 · 质量闭环产品化：把「机器验收」从内部机制变成看得见的卖点 ⭐⭐⭐

**为什么是第一**：这是两路调研确认的最稀缺资产（无人复制）+ 行业明确空白（evals
谈多做少）+ 成本最低（机制已存在，缺的是落表和呈现）。「每个交付都有机器验收记录、
质量分和返工轨迹」是采购者能一眼理解的信任卖点，直接回应「AI 干的活能不能信」。

落点（多数已在 harness-analysis 提出，此处升格为战略项）：
- 裁决与验收**落表**（现在 verdict 只进频道消息流）：`verdicts` 表挂 task_id/doc_id/
  逐条标准结果 → `engine.ts runVerification` 写入；
- **质量度量面板**（web）：按同事/项目/时间的一次通过率、返工原因分布、验收覆盖率；
- 返工上限后把「差距」结构化带给用户（哪条标准未满足、差在哪）而非只转 review；
- 多交付物全核验（现只核最后一份文档）；
- 对外叙事同步更新（README/GUIDE：「内建质量闸」段落）。

### D2 · 成本可预测性：做成第一梯队强项 ⭐⭐⭐

**为什么**：全行业被用户点名的通病（Lindy「贵且不可预测」、Agentforce TCO 3–5 倍、
Relevance「规模化后不可预测」），而 AITeam 已有消息级用量+账本+价格字段——距离
「任务开工前有估价、运行中有累计、超预算自动暂停待批」只差一层。国内市场正从纯
token 计费向资源包/预算制回摆，这个能力同时服务自用与未来商业化定价。

落点：
- 任务/项目级**预算字段**与运行中累计（修 harness-analysis 指出的「per-run 计数器
  revise 重跑归零」问题：预算按 task 累计持久化）；
- 开工前**成本预估**（按简报长度×档位×历史同类任务实际消耗）进入任务卡；
- 超预算 → 暂停 + 审批门恢复（复用现有 approval 机制）；
- 计费分列 cache_read/cache_creation/纯 input（已有字段，账本与面板展示拆开）。

### D3 · 团队知识底座（context layer）⭐⭐⭐

**为什么**：Dust 的粘性核心（月活采用率 90%+ 的来源是「共享上下文」而非 agent 本身）；
Agentforce 77% 失败率的教训是数据质量决定成败。AITeam 文档库目前只按频道列出、
无检索，知识不复利——这是与 Dust 级产品拉开差距的主因，也是「越用越好用」的
留存飞轮所在。

落点（本地优先约束下选轻量方案）：
- 文档库全文检索：SQLite FTS5（零新依赖）起步，`search_documents` 工具注入工作循环；
- 跨任务引用：交付物引用其他文档时记 doc→doc 边，任务简报自动带「相关历史交付」；
- 知识体检（差异化机会）：定期例行任务扫描文档库——过期标注、互相矛盾的数字、
  无来源的关键主张，输出体检报告（复用验收器的反编造判准）；
- 上传管道已通（markitdown/pdf/docx），缺的是「入库后被找到」。

### D4 · BYOA 编码/执行会话：按已有契约落地外部代理适配器 ⭐⭐

**为什么**：Helio 的编码会话（真终端/diff/可审计）和 Devin 的 Agent Command Center
是品类天花板能力；OpenClaw/ACP 潮流证明「旁挂成熟 CLI agent」比自建沙箱划算。
AITeam 已写好 EXTERNAL_AGENT_ADAPTER.md 契约（Task In/审批策略/事件回流），
这是把 TAM 从「知识工作交付」扩到「研发团队」的关键一步，但工程量最大，故排 D1-D3 之后。

落点：
- 第一个 adapter 接 Claude Code（headless `-p` 模式）或任意 ACP 兼容 agent：
  隔离目录 + 事件回流成 task activity + diff 作为交付物入文档库；
- 风险动作走现有审批门（契约里 approval_policy 已定义）；
- 验收闭环复用：外部 agent 的交付同样过校验者。

### D5 · IM 旁挂触达：钉钉/飞书/企微出入口 ⭐⭐

**为什么**：国内调研确认的第三条路——自建工作台（不受平台 API 审核束缚）+ IM 只作
触达渠道（OpenClaw/AionUi 已验证此模式）。「再开一个 App」是国内团队采用的最大阻力，
审批/@回流进 IM 能把日活拉回工作台。

落点：
- 出口先行（低成本）：审批请求、交付通知、blocked 求助推送到钉钉/飞书/企微群机器人
  webhook（server 侧一个 notifier 模块 + 设置页配置）；深链回桌面/网页（已有 aiteam:// 
  与 URL 参数路由）；
- 入口后置（高成本、需平台审核）：IM 内 @机器人 转发进频道，二期再评估。

### D6 · 互操作：对外 MCP server + 跟踪 A2A ⭐

**为什么**：互操作已成企业采购默认预期（信号 2）。AITeam 只做 MCP client 是单向的；
把自身暴露为 MCP server 后，Claude Code/Cursor/任何 MCP host 都能读写 AITeam 的
任务与文档——让 AITeam 成为「外部 agent 的协作记录系统」，反向获客。

落点：
- 只读起步：`aiteam-mcp` server 暴露 list_tasks/read_document/team_status 三个工具
  （复用现有 REST 面，鉴权走现有 session/token）；
- 写入面（create_task/comment）跟随审批门；
- A2A：2026 Q3 联合规范出台后再评估，现在不押注。

### 不做清单（同样重要）

- ❌ 浏览器/计算机使用：五方混战（OpenAI/Anthropic/Google/MS/Salesforce），成本高、
  无相对优势；通过 MCP 插件间接获得即可；
- ❌ 通用超级助手化：Manus/Genspark 赛道，与团队工作台心智冲突；
- ❌ 虚拟办公室式情感化可视化：团队视图已覆盖信息价值，装饰性投入后置；
- ❌ 自建 agent 间通信协议：等 A2A 收敛，避免私有协议成为企业渠道负资产。

## 4. 排序逻辑与节奏建议

| 方向 | 影响 | 成本 | 窗口紧迫度 | 依赖 |
|---|---|---|---|---|
| D1 质量闭环产品化 | 高（护城河显性化） | 低 | 高（无人复制期） | 无 |
| D2 成本可预测性 | 高（全行业通病） | 中低 | 中 | 无 |
| D3 知识底座 | 高（留存飞轮） | 中 | 中 | 无 |
| D4 BYOA 编码会话 | 高（扩 TAM） | 高 | 中（ACP 生态早期） | 契约已备 |
| D5 IM 旁挂触达 | 中（国内获客） | 低（出口）/高（入口） | 中 | VPS 部署 |
| D6 MCP server | 中（生态位） | 低 | 低 | 无 |

节奏建议：**D1+D2 并作一站**（同为「信任与账本」主题，改动集中在 engine/db/web 面板，
可与 VPS 迁移站并行）→ **D3 一站**（FTS5 起步小步快跑）→ **D4 独立大站**（先做
Claude Code adapter 单点打通）→ D5 出口与 D6 只读面见缝插针。

**一句话总结**：市场替我们验证了方向，也在快速填平「同台」的差异化；下一阶段的主线
不是加功能，而是把已有的质量闭环和成本账本从「引擎内部机制」升格为「用户可见、
可信、可比较的产品资产」，同时用知识底座和 BYOA 补齐决定天花板的两块短板。
